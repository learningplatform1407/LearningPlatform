# Interface languages (English, Romanian)

Both apps ship their interface in English and Romanian. Lesson content —
books, lecture text, questions, flashcards, announcements — is not
translated: it stays in the language its author wrote it in.

## Where the strings live

One catalogue per language in `packages/ui/src/i18n/messages/`, split by area
(`common`, `nav`, `settings`, `lesson`, `exams`, …). Web and mobile read the
**same keys**, so a screen says the same thing on both platforms.

- `en/` is the source of truth; its shape is the `Messages` type.
- `ro/` is typed `Messages`, so a missing, extra or misspelled key is a
  compile error, and `t("…")` only accepts keys that exist.
- `src/i18n/index.test.ts` also checks that every translation uses the same
  `{placeholders}` as the English and that none is empty.

## Using it

```tsx
const { t, language, locale } = useI18n(); // web: @/lib/i18n, mobile: @/lib/i18n
t("library.title"); // "Library" / "Bibliotecă"
t("common.failedToSave", { message }); // "{message}" is filled in
t("library.lessons", { count: 3 }); // plural, see below
formatPostDate(iso, language); // @lp/ui date/interval helpers take the language
```

Plurals are `plural({ one, few?, other })` entries picked by
`Intl.PluralRules`. Romanian needs all three: `one` (1 lecție), `few` (2–19,
and 101–119…: 3 lecții) and `other` (20+: 20 de lecții). English uses
`one`/`other`.

A sentence with markup inside it (web only) goes through `rich()`:
`rich(t("admin.import.flashcardsIntro"), { official: <strong>…</strong> })`,
so the word order stays in the catalogue.

## Which language is shown

The account's `settings.language` (`en` | `ro`; the API refuses anything
else) is the source of truth, saved on **Settings → Languages**.

- **Web.** The root layout reads the `lp-language` cookie, falling back to
  the browser's `Accept-Language`, and renders the first paint in that
  language with the right `<html lang>`. `LanguageSync` (signed-in layout)
  adopts the saved setting whenever `me` loads and rewrites the cookie, so a
  new browser switches as soon as you sign in, and the login page remembers
  the last language used. Reading the cookie makes every page render per
  request; text can't be fixed up by an inline script the way the theme is.
  Server actions translate their errors with `getServerTranslator()`.
- **Mobile.** `I18nProvider` follows the saved setting through the shared
  `me` query, so saving on the Languages screen switches at once. Signed out
  it uses the device language (Hermes' `Intl`, no native module).
- Supabase auth errors with a known `code` are translated
  (`authErrorMessage`); anything else shows Supabase's own English text, as
  do error messages the API returns in its response body.

## Adding a string

1. Add the key to the right file in `en/`, then the same key in `ro/`
   (TypeScript will insist).
2. Use `t("area.key")` on **both** platforms.
3. Tests render without a provider and read English, so existing assertions
   on English copy keep working.
